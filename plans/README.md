## Findings considered and rejected this wave (do not re-raise)

- **"Migrate all daemon bead reads to `bd --json` CLI polling"** (the bd
  docs' nominal guidance): REJECTED for steady-state reads — the
  nx-6lrf7/nx-veo5g crash loop was caused by request-path `bd`/`dolt`
  spawn storms, and the zero-spawn JSONL watcher + single-flight cold
  start (`cached-bead-source.ts`) is the deliberate remediation. bd's
  auto-flush rewrites the full JSONL, so deletes/prunes do propagate.
  Plan 056 fixes the JSONL path's real defects instead; bounded-cadence
  CLI spawns are reserved for genuinely CLI-only data (orphans/stale,
  plan 057).
- **Multi-repo hydration (`bd repo add/sync`) replacing the fleet walk**:
  hydration reads peer repos' JSONL *exports*, inheriting the same
  staleness the hand-rolled walk already has, while adding config and an
  experimental flag — no freshness win for `/exceptions`. Keep the walk;
  revisit only if federation's native Dolt sync becomes interesting.
- **Federation for homelab↔Mac sync**: current `bd dolt push/pull` over
  the git remote works; federation adds moving parts (peers, strategies,
  conflict pauses) without a demonstrated loss. Revisit if sync
  collisions persist AFTER plan 059's merge-slot serialization.
- **`bd compact` (AI history summarization)**: token cost for negligible
  benefit at this store size; prune/flatten (plan 062) is the right tool.
- **beads MCP server**: docs themselves recommend CLI+hooks over MCP when
  a shell is available (token cost); the repo is CLI-native.
- **`bd rename-prefix` / ID scheme changes**: no problem solved (prefix
  `nx-` is stable).
- **`bd swarm create` / coordinator orchestration**: single-coordinator
  repo. CORRECTED 2026-07-19 (second pass): `bd swarm validate` (ready
  fronts, worker-session estimates, cycle detection — a machine-computed
  wave-plan.json) and `bd swarm status` are read-only and ADOPTED into
  plan 061's pilot; only the coordinator half stays rejected.
- **`TriageItem.swift` as a beads consumer**: mis-association — it belongs
  to the mx cross-source triage feature, not beads.
