nx fires TTS + banner notifications when Claude Code sessions reach checkpoints across a peer-to-peer Tailscale fleet. Today it fans out by project + a manual meeting toggle only. This document explores layering a presence vector (per-device context) under a priority rules engine so a notification reaches the right surface — Mac banner, room-audible TTS, phone, or wrist — and stops where it should. Findings were produced by 8 parallel research agents and hardened by an adversarial critique pass; claims are tagged verified (code-grounded) or corrected (the critique overturned the first draft).

The Presence Vector

The canonical per-user state object the agent holds, fleet-merged across Macs. Every field carries source + updatedAt (drives staleness) + confidence. Past-TTL ⇒ unknown, never a stale truth.

Two gaps the critique surfaced this must answermacHost is now first-class because cross-machine delivery — a notification from a session on Mac A while you're at Mac B — is the core "right surface" promise and was unspecified. Fleet-merge also needs a tie-breaker (most-recent-heartbeat wins) when two Macs both report onConsole.

Routing Rules Engine

Model choice: priority-ordered condition → action, first-match-wins. It maps 1:1 to how the rules were stated, is deterministic and drag-reorderable, and critical-bypass is just rule 0. The decision table survives as the test harness.

Model trade-off
ModelVerdictWhy
Decision table keyed by vectortest oracle only2N cells, can't express time / rate / timers
Embedded DSL / scriptingrejectYAGNI, unsafe, un-renderable in a settings UI
Priority-ordered rule listchoose1:1 with stated rules; first-match deterministic; critical = rule 0; table = test harness

Action shape (closed struct)

Disambiguation the vision conflatesstopPropagation = the CC Stop-hook pipeline (does the parent session continue). Channel routing = deliverTo[]. They're orthogonal.

The 8 rules — resolved per Q1–Q4 (active Mac beats bedtime)

first-match-wins · top → bottom
# Rule 0 — CRITICAL  (Q4: severity = error/failure hook OR exit-code/keyword)
when: severity==critical AND NOT global_kill
  → all channels · simultaneous · interruptionLevel:timeSensitive · collapseId · escalate
  # Q4b: .timeSensitive — NO Critical Alerts entitlement; you whitelist nx in Sleep Focus

# Rule 1 — Active on Mac  (Q1: beats bedtime — TTS at your desk even at 2am)
when: mac_active AND NOT in_meeting
  → banner+tts · deliverTo:[macHost]

# Rule 2 — In meeting -> HOLD, post-meeting summary  (held queue DB-backed)
when: mac_present AND in_meeting
  → digest · holdUntil:(meeting_ends_at ?? now+60m)+2m → summary banner+tts
  # Q2: hold iff (camera OR mic) AND (app OR calendar); buffer configurable
  # GUARD: if flush lands inside bedtime AND mac idle -> deliver silent, no TTS

# Rule 3 — BEDTIME  (Q1: only when Mac NOT active)
when: is_bedtime AND NOT mac_active
  → banner · ding:false · tts:false · deliverTo:[phone] · passive · redact:generic

# Rule 4 — Mac off/locked + phone home -> speak into the room
when: (NOT mac_active OR mac_locked) AND phone_present AND phone_home
  → tts · deliverTo:[macHost]
  # Q5: phone_home from agent-side Tailscale/LAN + phone SSID — no Always-location

# Rule 5 — Mac off + phone away
when: (NOT mac_active OR mac_locked) AND phone_present AND NOT phone_home
  → banner · tts:false · deliverTo:[phone] · active

# Rule 6 — phone active recently   (phone_active_recently replaces phoneLocked)
when: phone_present AND phone_active_recently
  → banner+ding · deliverTo:[phone] · active

# Rule 7 — phone idle -> buzz the wrist   (Q3: simultaneous fan-out)
when: phone_present AND NOT phone_active_recently
  → banner+ding · deliverTo:[phone,watch] · simultaneous · timeSensitive · collapseId
  # shared collapseId dedups; ack on one device withdraws the other

# Rule 8 — terminal fallback  (vector all-unknown / nothing reachable)
when: true
  → deliverTo:[dashboard] · digest    # nothing silently dropped; unacked tray
Staleness split — the fail-open / fail-safe resolutionFor any field a matched rule depends on that is unknown: non-critical ⇒ fail-safe (demote to silent/digest), critical ⇒ Rule 0 already fired everywhere (fail-open). Per-severity, not global. This is why Rule 4 (depends on the often-unknown phone_home) degrades to digest instead of blasting TTS into a room nx can't confirm is occupied.

Architecture & Data Flow

Per-device reporters push context to a new agent-held presence store; the router reads the vector at dispatch time and fans out to the resolved channels. Detection is per-platform; routing is central.

reporters -> agent presence store -> channel fan-out
 REPORTERS                          AGENT (apps/agent)                 DELIVERY
 ---------                          ------------------                 --------
 mac: PresenceObserver.swift --+    presence-context.ts (NEW,          mac banner+TTS
   camera/mic, lock, Focus DB,  |      mirrors meeting-state but        (macHost-routed --
   EventKit, SSID               +-->   DB-BACKED held queue)            cross-machine!)
 mac: Bun CLI fallback --------+    per-user PresenceVector, TTL'd
   (ioreg/pmset/pgrep/arp)          lifecycle-bus: PresenceChanged     APNs -> iOS
                                       |                               (collapseId)
 ios: PresenceReporter -------->    manager.send()
   CLLocationManager,                 +- meeting buffer (EXISTS)       APNs -> watch token
   INFocusStatus, HKSchedule          +- presence hold (NEW, durable)  (collapseId, timeSensitive
   POST /presence/report (NEW)        +- router.findMatchingRule(   -- same logical notif,
   + future silent-push pull              vector, event)               no double-buzz)
                                       |- rules -> Action -> resolve
                                       +- ack on any device ->
                                          withdraw siblings by collapseId
Honest constraintsiOS can't poll in background (event-driven only). Apple — not nx — arbitrates the final watch-vs-phone delivery. Presence socket down ⇒ router ignores presence rules and falls back to today's meeting_behavior buffering (never a hard failure).
Held queue MUST be DB-backedmeeting-state.ts is in-memory and loses buffered notifications on every agent restart (systemd reload, post-merge deploy fan-out, OOM). Inheriting that for a 60m-2h presence-hold window is a data-loss bug — the held/digest queue must persist, not just a holdReason column.

Decisions — resolved 2026-06-19

All six open questions answered by Leo. These are now binding for the Phase 1 spec; the rules (Sec 3) and phase plan (Sec 7) above already reflect them.

Q1Active Mac beats bedtimeRoom-TTS wins when you're demonstrably at your desk — Rule 1 (mac_active) fires even at 2am. Bedtime (Rule 3) only suppresses when the Mac is not active (you're away / idle).
Q2AND-gate, buffer configurableHold only when (camera OR mic) AND (meeting-app OR calendar-busy) — camera-alone never hard-holds. The 2-min post-meeting buffer is user-adjustable.
Q3Simultaneous fan-out (trial)Non-critical fans out to all eligible surfaces at once; ack on one device withdraws the others via collapseId. Trying this before falling back to an escalation ladder.
Q4Critical = error hooks + exit-code/keywordAn event is critical when a Stop/error hook fires or an exit-code / keyword heuristic (FATAL, blocked, payment) trips. Per-project floor + explicit tag deferred to Phase 4.
Q4b.timeSensitive, no entitlementCritical ships with interruptionLevel: .timeSensitive; you whitelist nx in Sleep Focus → Allowed + enable Time-Sensitive per device. No Critical Alerts application — no Apple review, near-unconditional reach because it's your fleet.
Q5Tailscale home detection + SSID, no Always-locationphone_home derives from the agent reading tailscale status (LAN-direct peer = home) corroborated by a When-In-Use phone SSID on foreground. Zero iOS location permission; geofencing dropped. Most-recent source wins on conflict.
Q6Single-user, fleet-mergedVector keyed to one user (you), merged across your Macs to pick the live host. No multi-tenant presence merging built — matches the P2P Tailscale fleet.
NextPhase 1 is unblocked. Scaffold with /feature context-aware-routing — Rules 1 & 2 on idle + lock + meeting-state, DB-backed held queue, Routing settings tab.
