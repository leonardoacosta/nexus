01 · The Board

Main window — project structure board

The project rail is the only selector — All at the top, no redundant header dropdown. Proposals render as expandable first-class rows with live task rollups; orphan beads (from /beads/unlinked) sit at the same top level, badged ORPHAN so unplanned work is never invisible. In All mode each row carries a project tag. Presence is one homelab dot — the only agent this dashboard is expected to reach. The TTS ticker is the kept notification surface — ambient, one line, never a modal.

02 · Information Architecture

Seven surfaces in, one spine out

The board is the app. Sessions become a rail + attach affordance hanging off the projects they belong to. Notifications/TTS become the ambient ticker + a history drawer. Everything operational (credentials, integrations, sources) leaves the daily surface and moves behind a Settings pane. Failures and health collapse into badges on the thing that failed, not destinations of their own.

Keep, demote, deprecate

Capability level demoted to a tag on proposal rows — the proposal is the unit Leo triages, matching bd's feature-primary priority model. Decide deckAbsorb Swipe-card approval queue (~820 ln off-sidebar) becomes approve/reject actions on proposal rows + detail rail — the approval gate lives where the proposal lives.
SessionsKeep · reframed Session rail under each project + live count in the project list. A session is context about a project, not a peer destination.
TTS + NotificationsKeep · ambient One-line ticker at top + history drawer (⌘H) + per-proposal recent-TTS in the detail rail. Never a modal, never a tab. 04 · Data Contract

Already shipped — the board is a rendering problem

The add-bead-proposal-roadmap-surface capability already landed the aggregation: GET /roadmap?project=<code> returns capabilities → proposals with BeadRollup progress, and GET /beads/unlinked?project=<code> returns exactly the orphan set. Both degrade to empty on bd failure, never 500. The only new agent work is an All aggregator (fan-out across the project registry, merge, tag rows with project code) and task-level descriptions in the rollup.

05 · Ambient Layer

Notification drawer — where TTS history and failures live

Summoned by ⌘H or the bell; slides over the board's right edge, never a tab. Inherits everything NotificationsView does today — grouped history, per-row replay, meeting mode, drop-TTS — and absorbs Failures: a failure is a red entry here plus a badge on the affected row, not a destination. TTSObserver keeps speaking regardless; this is just where the history is read back.

06 · Attach

Attach sheet — the PTY viewer, summoned not visited

07 · Settings

Settings pane — credentials, integrations, sources, voices

The operational surfaces leave the daily nav and become tabs in one Settings window (⌘,). Integration health still reaches you without visiting this pane: a degraded integration is an amber dot on the tab AND a drawer entry. Sources keeps its registry editing (agents.toml, discovered projects, hidden toggles) — its daily output is already the board's project rail.
