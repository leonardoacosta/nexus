01 · The Board

Main window — project structure board

Proposals render as expandable first-class rows with live task rollups; orphan beads (from /beads/unlinked) sit at the same top level, badged ORPHAN so unplanned work is never invisible. In All mode each row carries a project tag. The TTS ticker is the kept notification surface — ambient, one line, never a modal.

02 · Information Architecture

Seven surfaces in, one spine out

The board is the app. Sessions become a rail + attach affordance hanging off the projects they belong to. Notifications/TTS become the ambient ticker + a history drawer. Everything operational (credentials, integrations, sources) leaves the daily surface and moves behind a Settings pane. Failures and health collapse into badges on the thing that failed, not destinations of their own.

03 · Disposition

Keep, demote, deprecate

SurfaceVerdictWhere it goes
Roadmap + SpecsBecome the app Merged into the main board — today they are two separate tabs rendering the same beads data (RoadmapView 246 ln, SpecsView 791 + SpecDetailView 401 ln). Spec content, approval status, and sessions render in the detail rail. Capability level demoted to a tag on proposal rows — the proposal is the unit Leo triages, matching bd's feature-primary priority model. BeadStatusGlyph and the Roadmap/Specs view models are direct build-on material.
Projects tabAbsorb The board's project rail IS the projects view (counts, presence, hidden toggle). ProjectsView + ProjectAccordionRow (400 ln) retire.
Decide deckAbsorb Swipe-card approval queue (~820 ln off-sidebar) becomes approve/reject actions on proposal rows + detail rail — the approval gate lives where the proposal lives.
SessionsKeep · reframed Session rail under each project + live count in the project list. A session is context about a project, not a peer destination.
TTS + NotificationsKeep · ambient One-line ticker at top + history drawer (⌘H) + per-proposal recent-TTS in the detail rail. Never a modal, never a tab. The drawer inherits everything NotificationsView (541 ln) does today — history, replay, meeting mode, drop-TTS — and TTSObserver (813 ln) is untouched: it subscribes to the NotificationFired SSE bus, not to any view.
HealthAbsorb Machine presence dots in the titlebar + a health badge that expands to the process table on demand. HealthView (490 ln) stops being a destination.
PTY ViewerAbsorb Becomes the Attach action on a session row. The viewer stays as a sheet/window you summon, not a place you visit.
FailuresAbsorb Failure badge on the affected project/session row + entries in the notification drawer. A failures tab is a graveyard nobody checks.
CredentialsDemote Settings pane. Operational config, touched monthly — zero reason to sit beside daily triage.
IntegrationsDemote Settings pane, same reasoning. Health of an integration surfaces as a badge, not a page.
SourcesDemote Settings pane (project/agent registry management). The output of sources — the project list — is the board's rail.
Older menubar app (apps/swift/nexus/)Deprecate candidate A parallel mac app with its own Models.swift/NexusClient.swift copy — a standing drift source. Fold its at-a-glance popover into nexus-mac's menu-bar extra, or retire it. Leo's call (clean replacement vs keep).
Analytics / Wave-plans / misc routesDeprecate candidates Agent routes with no surviving primary surface get a usage audit; anything the board and drawer don't consume within a release gets removed per the clean-replacement default.
04 · Data Contract

Already shipped — the board is a rendering problem

The add-bead-proposal-roadmap-surface capability already landed the aggregation: GET /roadmap?project=<code> returns capabilities → proposals with BeadRollup progress, and GET /beads/unlinked?project=<code> returns exactly the orphan set. Both degrade to empty on bd failure, never 500. The only new agent work is an All aggregator (fan-out across the project registry, merge, tag rows with project code) and task-level descriptions in the rollup.
