Finding 06
Dual Session Tracking
Sessions are tracked in both an in-memory Map and a Postgres table with no synchronization mechanism. Two sources of truth that can diverge silently.
Before -- Dual Source of Truth
session event-->in-memory Map
session event-->Postgres table
No sync between stores. Reads may return stale or conflicting data depending on which source is queried.
After -- Single Source + Cache
session event-->Postgres
-->read-through cache-->consumers
Postgres is the single source of truth. In-memory Map becomes a read-through cache with TTL invalidation.
