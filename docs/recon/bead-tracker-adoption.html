Making nx the bead-tracker that knows its own roadmap

Two mature Beads dashboards, cross-referenced against the nx stack (Swift dashboard suite + Bun agent daemon + Postgres/drizzle). What to steal, what to adapt — and the one thing neither of them has that becomes nx's moat.

jordanhindo/beadboard · Next.js + Dolt · 53★ · MIT
w3dev33/beads-task-issue-tracker · Tauri + Nuxt · 58★ · frozen → PaiR

The moat

Both repos prove bead visualization + multi-agent coordination is a solved, polished problem — so steal their pure derivation logic instead of reinventing it. But both have zero openspec / proposal / roadmap linkage. beadboard has 0 code hits for openspec; the tracker's specId is a labeled text box. nx's defensible surface is the openspec × bead × roadmap join — built on top of their bead derivations, not against them.

Steal & Adapt — before / after

Ordered keystone-first, then quickest wins. Effort is against the nx stack.

Keystone · Steal effort: medium · both repos

spec_id as the bead ↔ openspec proposal join key

tracker: lib.rs ~2652 --spec-id · IssuePreview.vue:886  |  beadboard: gap (0 hits)
Before — the prior art
Beads ships a first-class --spec-id field, but the tracker renders it as inert mono text ({{ issue.specId }}) with no parsing, navigation, or validation. beadboard doesn't touch proposals at all.
After — nx owns this
Populate spec_id with the openspec change-id on bd create. Model proposals in drizzle FK'd to bead_id/spec_id. Swift detail view renders it as a tappable link into proposal status + tasks.md progress + delta. Daemon reconciles specId ↔ openspec/changes/* on hook ingest. This is the roadmap surface nothing else has.
Stealeffort: small · tracker (B)

Dot-notation epic hierarchy + progress rollup

issue-helpers.ts · getParentIdFromIssue / groupIssues
Before
~40 lines of pure fns derive parent/children from the ID string (abc.1 → abc) + compute closedChildCount / childCount client-side.
After
Port to NexusShared (Swift) + the Bun agent. Menubar epic rows and any roadmap view get inline progress bars with zero schema change — hierarchy derives from the ID bd already emits.
Stealeffort: small · beadboard (S1)

Derived lanes + unblocks-ranked "what next"

kanban.ts · deriveBlockedIds / pickNextActionableIssue
Before
nx ranks work by priority/dependency. beadboard derives blocked-ness (any blocks target not closed) and ranks ready by priority → unblocks-count → recency.
After
Shared @nx/beads derivation module (blocked-set, unblocks-count, next-actionable tiebreak) feeding the statusline/roadmap-pulse and the Swift dashboard. Principled "do this next" pick for free.
Stealeffort: small · beadboard (S2)

Per-bead readiness checklist gate

kanban.ts · buildExecutionChecklist
Before
owner / no-open-blockers / acceptance-signal / executable-status rendered as a card checklist. nx gates at the openspec tasks.md level, not per-bead.
After
Render a readiness chip on each bead card; add an nx-only 5th check — "has an associated openspec proposal" — directly advancing the moat.
Stealeffort: small–med · beadboard (S3)

Coordination-as-audit-log envelope

coord-schema.ts · coord.v1 via bd audit record
Before
Agent/coordination events likely live in bespoke drizzle tables in nx's daemon. beadboard writes a versioned envelope into the tracker's own history.
After
Adopt a versioned coord.v* envelope for hook/agent events so they're self-describing + replayable, keeping Swift event consumers stable across schema evolution.
Adapteffort: medium · beadboard (A1)

bd-only-writer + never-throw importer

read-issues-dolt.ts · returns null, never throws
Before
nx's Postgres/drizzle is a third store beyond issues.jsonl. Drift risk between mirror and bd truth.
After
Discipline: bd CLI is the only writer; drizzle is a read projection rebuilt via a never-throw importer that degrades to direct JSONL parse. Steal the two-query in-memory-join shape.
Adapteffort: medium · beadboard (A2)

Focus-aware dependency graph

epic-graph.ts · buildWorkflowEdges (BFS edge-tagging)
Before
Selecting a node BFS-traces upstream blockers + downstream blocked, tagging edges to dim the unrelated. nx has no interactive dep graph in Swift.
After
Port to a SwiftUI/webview graph where selecting a bead dims unrelated edges; extend nodes to render openspec proposal status — a graph beadboard structurally cannot draw.
Adapteffort: medium · tracker (E, F)

Adaptive live-update cadence + CLI serialization

useAdaptivePolling · BD_PROJECT_LOCKS mutex
Before
Tiered 5s active / 30s blurred / 60s idle / paused-hidden, cheap mtime-check before expensive fetch. Per-project mutex + 10s sync cooldown prevents concurrent-DB corruption.
After
Replace fs-watch with Postgres LISTEN/NOTIFY over the existing socket spine; keep the tier table + cheap-check-first gating. The Bun dispatcher shelling to bd needs exactly this mutex + debounce.
Adapteffort: medium · tracker (C, D)

Dual-filter table + 3-panel control-panel IA

issue-helpers.ts filterIssues · pages/index.vue
Before
Inclusion + exclusion/inverse filters, search short-circuits everything, per-project persisted state. Left dashboard / center table / right detail — "observe AI, step in" framing (no board).
After
SwiftUI-native reimplementation over Postgres queries; matches nx's menubar-dashboard intent. Add a proposal-status column the table can group/filter on.

Monitor

  • bb-pi embedded orchestrator — Pi runtime + archetypes/templates/reservations for multi-agent scope-locking. "Under construction" w/ known races; nx has its own daemon. Watch the reservation model, don't couple.
  • beadboard-driver skill — 9-step agent operating contract as an installable skill. Overlaps nx's slash-command spine; watch the packaging.
  • Multi-backend abstraction (bd / br / SQLite) — the tracker's built-in engine isn't even in the shipped tree. Watch only if bd server-mode regresses.
  • cleared:{id} sentinel — SQLite UNIQUE workaround; unlikely on Postgres.

Skip

  • Dolt as the datastore — nx is committed to Postgres/drizzle. Take the fallback discipline (A1), not the engine.
  • Next.js / Nuxt UI shells — nx's surface is Swift. Reference the information architecture (lenses, 3-panel), not the component trees.
  • Windows path canonicalization, Remotion video, Chokidar+SSE / notify fs-watch transport — nx targets macOS/iOS/watchOS over a Bun socket spine.
  • Filesystem attachment convention (.beads/attachments/{id}/) — nx has Postgres + real object storage.
  • Roadmap / proposal-content surfacing — doesn't exist in either repo. Not a skip of prior art; it's nx's greenfield.
