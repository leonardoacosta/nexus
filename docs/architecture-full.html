Nexus

system architecture — 3 crates, 14 services, 45.8K lines of rust

Per-machine daemon + terminal UI for managing Claude Code sessions across a Tailscale mesh. The agent provides session lifecycle, health monitoring, and a full notification engine. The TUI aggregates sessions from all agents via gRPC.

Meeting queue (new). When a meeting is detected (mic active, Teams/Zoom window, or FaceTime), notifications are held per-project. A 15-second poll loop checks when the meeting ends, then delivers a summary: "3 updates for OO while you were away. First: Build passed. Latest: Deploy complete."
Protocol Unix Socket Events

Claude Code hooks communicate with the agent via newline-delimited JSON on /tmp/nexus-agent.sock. Two message types: fire-and-forget events (tagged by "event") and request-response commands (tagged by "command").

EventDirectionPurpose
session_startCC → AgentRegister session (id, project, cwd, model, pid, branch)
session_stopCC → AgentUnregister session
session_heartbeatCC → AgentKeep session marked active
notificationCC → AgentTTS/banner/APNs delivery (with message, type, channels)
answerCC → AgentDispatch answer to CC session via tmux send-keys
agent_spawnCC → AgentSub-agent started within a session
agent_completeCC → AgentSub-agent finished
telemetryCC → AgentCost, rate-limit, token counts, tool failures
session_summaryCC → AgentEnd-of-session aggregate stats
deploy_statusCC → AgentDeployment lifecycle events
CommandDirectionPurpose
mode_queryReq → RespQuery current notification mode
mode_setReq → RespSet notification mode (full/noduck/system/silent)
mode_cycleReq → RespCycle to next notification mode
historyReq → RespRecent notification history
type_set / type_clearReq → RespPer-type notification mode overrides
notification_rulesReq → RespQuery per-project notification rules
notification_setReq → RespMutate per-project rules, persist to TOML

Analysis Scope Breakdown
Identity question. ~82% of codebase is notification infrastructure, ~18% is the original TUI/session harness. Nexus has evolved from "TUI SSH harness" into "developer operations daemon." The notification engine alone (20 files, 8.1K lines) has more code than the TUI.
