2. Session Lifecycle

From CC hook trigger through registration, interaction, dead session detection, and kill escalation.

sequenceDiagram
  participant CC as CC Hook
(nexus-register)
  participant Sock as Unix Socket
(/tmp/nexus-agent.sock)
  participant Dispatch as Socket Dispatch
  participant SM as Session Manager
  participant Bus as Lifecycle Bus
  participant DB as PostgreSQL
  participant Dash as Next.js Dashboard
  participant HTTP as HTTP :7400
  participant WS as WebSocket
(stream/interact)
  participant Stream as Stream Manager

  rect rgb(45, 31, 78)
    Note over CC,Sock: Session Start Trigger
    CC->>Sock: NDJSON {"event":"session_start","session_id":"abc"}
    Sock->>Dispatch: SocketEvent
    Dispatch->>SM: handleWatcherEvent({type:"session_start"})
    SM->>SM: Create Session (status: active, in-memory Map)
    Dispatch->>Bus: emit("SessionStarted", {sessionId, project, model})
    Bus-->>DB: upsert session row (via session routes)
  end

  rect rgb(13, 31, 48)
    Note over CC,Bus: Session Heartbeat
    CC->>Sock: {"event":"session_heartbeat","session_id":"abc"}
    Sock->>Dispatch: SocketEvent
    Dispatch->>SM: handleWatcherEvent({type:"session_update"})
    SM->>SM: Update lastHeartbeat timestamp
    Dispatch->>Bus: emit("SessionHeartbeat")
  end

  rect rgb(45, 34, 0)
    Note over Dash,Stream: Session Interaction
    Dash->>HTTP: GET /sessions (x-nexus-secret)
    HTTP->>SM: getAll()
    SM-->>HTTP: Session[]
    HTTP-->>Dash: JSON response

    Dash->>WS: Upgrade /sessions/abc/stream?token=secret
    WS->>Stream: attach PTY, addViewer(ws)
    Stream-->>WS: PTY output (fan-out to viewers)

    Dash->>WS: Upgrade /sessions/abc/interact?token=secret
    WS->>Stream: setInteractiveWriter(ws)
    Note over WS,Stream: Bidirectional PTY I/O (keyboard in, terminal out)
  end

  rect rgb(48, 13, 13)
    Note over SM,SM: Dead Session Detection
    SM->>SM: sweepIdle() every 60s
    SM->>SM: Check lastHeartbeat > 5min idle threshold
    SM->>SM: status: active -> idle -> stale
    SM->>SM: Check /proc/{pid} exists
    Note over SM: If /proc missing: status -> ended
    SM->>SM: Ended TTL 1h: evict from Map
  end

  rect rgb(48, 13, 30)
    Note over SM,Bus: Session Kill (SIGTERM -> SIGKILL)
    SM->>SM: kill(pid, SIGTERM)
    SM->>SM: Wait grace period
    SM->>SM: kill(pid, SIGKILL) if still alive
    SM->>Bus: emit("SessionStopped", {sessionId})
    Bus->>DB: update session status
  end

3. Credential Management

Encrypted credential pool with lease/release/cooldown lifecycle, usage polling, and pre-rotation at 85% utilization.

sequenceDiagram
  participant Admin as Admin / CLI
  participant HTTP as HTTP :7400
  participant Pool as Credential Pool
  participant Enc as Encryption
(AES-256-GCM)
  participant DB as PostgreSQL
(credentials table)
  participant API as Anthropic API
  participant Bus as Lifecycle Bus

  rect rgb(13, 31, 48)
    Note over Admin,DB: Credential Storage
    Admin->>HTTP: POST /credentials {name, type, value}
    HTTP->>Pool: add({id, name, type, value_plaintext})
    Pool->>Enc: encrypt(value, NEXUS_ENCRYPTION_KEY)
    Enc-->>Pool: ciphertext (AES-256-GCM)
    Pool->>DB: INSERT credential (valueEncrypted, status: available)
    Note over DB: Stored at ~/.config/nexus/credentials/
Encrypted at rest in PostgreSQL
  end

  rect rgb(45, 31, 78)
    Note over HTTP,DB: Lease / Release Lifecycle
    HTTP->>Pool: lease(type: "anthropic", leasedBy: "session-abc")
    Pool->>DB: BEGIN TRANSACTION
    Pool->>DB: SELECT ... WHERE status=available
ORDER BY rate_limit_count ASC
FOR UPDATE LIMIT 1
    DB-->>Pool: credential row
    Pool->>DB: UPDATE status=leased, leasedBy, leasedAt
    Pool->>DB: COMMIT
    Pool->>Enc: decrypt(valueEncrypted, key)
    Pool-->>HTTP: CredentialRow (decrypted value)

    Note over HTTP,Pool: ... session uses API key ...

    HTTP->>Pool: release(credentialId)
    Pool->>DB: UPDATE status=available, leasedBy=null
  end

  rect rgb(48, 13, 13)
    Note over Pool,API: Rate Limit / Cooldown
    HTTP->>Pool: reportRateLimit(credentialId)
    Pool->>DB: UPDATE rate_limit_count++, status=cooldown
cooldownUntil = now + 5min
    Pool->>Bus: emit("CredentialSwap", {credentialId, reason})

    Note over Pool,DB: Cooldown Recovery (periodic)
    Pool->>DB: SELECT WHERE cooldownUntil < now
    Pool->>DB: UPDATE status=available (batch)
  end

  rect rgb(45, 34, 0)
    Note over Pool,API: Usage Polling and Pre-Rotation
    loop Every 300s
      Pool->>API: GET /v1/usage (per credential)
      API-->>Pool: {used, limit, percent}
      alt utilization >= 85% (prerotateThreshold)
        Pool->>Pool: Mark credential for cooldown
        Pool->>DB: UPDATE status=cooldown
        Pool->>Bus: emit("CredentialSwap", {reason: "pre-rotation"})
        Note over Pool: Next lease() picks a fresh credential
      end
    end
  end

  rect rgb(13, 31, 48)
    Note over Pool,DB: Stale Lease Recovery
    Pool->>DB: SELECT WHERE status=leased
AND leasedAt < now - 30min
    Pool->>DB: UPDATE status=available (batch)
    Note over Pool: Prevents credential exhaustion
from crashed sessions
  end

4. Peer Federation

Peer-to-peer agent mesh via Tailscale. Agent machines (omarchy, other dev servers) emit lifecycle events and forward them to the primary (macbook) via WebSocket federation. The primary's NotificationEngine handles all notification delivery — agent machines do not deliver notifications locally.

(omarchy)
  participant PC as Peer Connector
(omarchy, role=agent)
  participant Bus as Lifecycle Bus
(omarchy)
  participant WS as WebSocket
ws://macbook-pro:7400
  participant MBConn as Peer Connector
(macbook, role=primary)
  participant PBus as Lifecycle Bus
(macbook)
  participant FN as Federation Notify
(macbook)
  participant NR as Notification Router
(macbook)

  rect rgb(13, 31, 48)
    Note over TOML,PC: Discovery (agent role)
    PC->>TOML: Read ~/.config/nexus/agents.toml
    Note over TOML: self_name = "omarchy"
role = "agent"
[[agents]] name="macbook"
host="macbook-pro" port=7400
    PC->>PC: Filter out self (omarchy)
Build peer list: [macbook]
    PC->>Bus: setOrigin("omarchy")
    Note over PC: Agent role: emit events,
forward to primary. No local delivery.
  end

  rect rgb(45, 31, 78)
    Note over PC,WS: Outbound WebSocket Connection (agent -> primary)
    PC->>WS: Connect ws://macbook-pro:7400/ws/federation
    Note over WS: x-nexus-secret header for auth
    WS-->>PC: Connection established
    PC->>PC: Reset attempt counter, drain buffer
    Note over MBConn: macbook (role=primary) accepts
inbound connections from agents
  end

  rect rgb(45, 34, 0)
    Note over Bus,PBus: Lifecycle Event Forwarding (omarchy -> macbook)
    Bus->>Bus: Session started locally on omarchy
    Bus->>PC: onAny(envelope) [source: local]
    PC->>WS: JSON.stringify(envelope)
    WS->>MBConn: receive envelope
    MBConn->>PBus: injectPeerEvent(envelope) [source: peer]
    Note over PBus: Peer bus emits with source=peer
Echo suppression: connector won't re-forward
  end

  rect rgb(48, 13, 13)
    Note over WS,PC: Disconnect and Reconnect (agent side)
    WS--xPC: Connection lost (code: 1006)
    Note over PC: Buffer events on agent (max 1000 per peer)
    Bus->>PC: onAny(envelope)
    PC->>PC: buffer.push(envelope) [primary offline]

    loop Exponential Backoff
      Note over PC: attempt 0: wait 1s
attempt 1: wait 2s
attempt 2: wait 4s
attempt 3: wait 8s
... max 30s
      PC->>WS: Reconnect attempt
    end

    WS-->>PC: Connection restored
    PC->>PC: drain buffer
    PC->>WS: Replay buffered events (in order)
    Note over PC: Reset attempt counter to 0
  end

  rect rgb(13, 48, 30)
    Note over PBus,NR: Primary-Only Notification Delivery (macbook)
    PBus->>FN: onAny(envelope) [source: peer]
    FN->>FN: Filter: only process source=peer
    FN->>FN: Map event to notification
(SessionStarted, SpecTransition, etc.)
    FN->>NR: routeNotificationParallel(notification)
    NR->>NR: findMatchingRule(notification)
    NR->>NR: Dispatch to channels (TTS/ElevenLabs,
desktop notifications, iMessage)
    Note over NR: omarchy does NOT deliver
notifications -- primary role only
  end

5. Notification Pipeline

Events originate on agent machines (omarchy, other dev servers) and are forwarded to macbook (role=primary) via WebSocket peer federation. The primary's NotificationEngine applies per-project routing rules and delivers via TTS/ElevenLabs, system say, desktop notifications, and iMessage. Agent machines collect and forward — they do not deliver notifications locally.

  rect rgb(45, 34, 0)
    Note over Fed,Rules: Primary Routing Decision (macbook)
    Fed->>Router: routeNotificationParallel(notification)
    Router->>Rules: findMatchingRule(notification)
    Note over Rules: 1. Match project-specific rule
2. Match wildcard rule (no project)
3. Fall back to DEFAULT_RULES
   [channels: ["desktop"], meeting: "buffer"]
    Rules-->>Router: NotificationRule {channels, meeting_behavior}
  end

  rect rgb(13, 48, 30)
    Note over Meeting,Buffer: Meeting-Aware Buffering (macbook)
    alt Meeting active (meeting_behavior: "buffer")
      Router->>Buffer: insertNotification(db, row)
      Buffer->>DB: INSERT (status: queued)
      Buffer->>Buffer: Track in pendingIds ring buffer (max 1000)
      Note over Buffer: Persist metadata to
~/.config/nexus/buffer-meta.json
    end
    alt Meeting ends
      Meeting->>Buffer: Flush buffered notifications
      Buffer->>DB: SELECT WHERE status=queued
      loop Each buffered notification
        Buffer->>Router: route(notification)
      end
    end
  end

  rect rgb(48, 13, 30)
    Note over Router,IMsg: Primary-Only Multi-Channel Delivery (macbook)
    Router->>Router: Promise.allSettled(channels)
    par TTS delivery
      Router->>TTS: sendTtsNotification(row)
      TTS->>TTS: POST /v1/text-to-speech/{voiceId}
(ElevenLabs API) or system say

      TTS-->>Router: success
    and Desktop delivery

      Desktop-->>Router: success
    and iMessage delivery
      Router->>IMsg: sendIMessageNotification(row)
      IMsg-->>Router: success
    end
    Router->>Router: Collect {delivered[], failed[]}
    Router->>DB: UPDATE status=delivered, sentAt=now
  end
